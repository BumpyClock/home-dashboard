# v.00
- Unreleased, no update yet. Build dev builds from source.
- Photo slides/fades keep stable image slots. Frame builds prepare the next photo texture while idle and retain a bounded set of prepared textures. Full-screen cache persistence uses a separate bounded writer so decoding can continue after UI publication.
- Photo cards retain rounded corners through both transition slots. Navigation discards obsolete texture preparation, and photo demand controls upload deferral independently of diagnostics. Rotation closes interrupted transition traces; animation-gap analysis excludes idle gaps touching only a transition boundary.
- Optional `FRAME_GPU_FENCE_TRACE=1` adds zero-timeout GPU fence diagnostics during an explicit trace capture. Normal operation and ordinary tracing retain the existing display synchronization.
- Renderer/backend tracing and GPU fence diagnostics now require an explicit `PF_RENDER_TRACE=1` build. Normal frame builds retain texture preparation without diagnostic renderer patches. Prewarm support is explicitly registered by the patched renderer, not inferred from Cargo features.
- Opt-in local performance traces now correlate photo jobs, cache work, UI updates, animation boundaries, and frame renderer/display stages. Captures expire after at most 180 seconds and report dropped events. Frame metrics schema 3 adds animation state while retaining existing fields.
- Full-screen photos now reuse display-sized files in `FRAME_THUMB_CACHE/full` on later visits and restarts. The disk cache is capped at 128 MiB and uses JPEG quality 90. Cold results are queued for display before encoding the cache copy.
- Cover resizing writes only the final crop using the same Triangle sampling, reducing temporary allocation while preserving the uncached pixels.
- Time zone setting: Settings tab picker (System + 14 IANA zones, stored by name in `settings.json` as `"timezone"`). The clock, calendar day, weather hour labels, and `FRAME_NIGHT_*` windows now follow the configured zone instead of system local time; `System` follows the OS zone.
- Photos tab: thumbnails appear sooner and scrolling is smoother. Decodes still wanted are no longer restarted on every scrolled row; grid thumbnails stay loaded across tab changes and the screensaver and have their own cache; scrolling one row re-uploads only that row's tiles; tiles round their corners with a mask ring instead of an offscreen-layer clip; the startup scan reads only JPEG headers for the EXIF date.
- Photos tab: grid thumbnails are built once per photo and stored on disk (`FRAME_THUMB_CACHE`), including a background pass while the frame is idle; later visits and restarts load them directly. The production unit stores them in `/var/cache/photoframe-proto/thumbs`.
- Photos: large JPEGs decode at a reduced size when the grid thumbnail, Home card or full-screen photo is much smaller than the file, so photos appear sooner and use far less memory while loading.
- Photos tab uses the theme's page background and text colors instead of a fixed dark backdrop.
- Screensaver (portrait): the clock sits at the bottom left, with weather and the next event on the same row at the right edge, matching landscape.
- Added macOS cross-build container and USB serial deploy runbook (`docs/serial-deploy.md`, `scripts/build-frame-container.sh`, `scripts/frame-console.py`). The sysroot packages are fetched over HTTPS and checked against the repo database SHA256 before use. Frame console credentials live in gitignored `.claude/frame-credentials.json`, never in the repo.
- Photos: decoding uses two threads by default (`FRAME_DECODE_THREADS`, 1 to 3), so the first Photos grid visit and the idle thumbnail pass finish sooner; on the frame, building all 66 stored thumbnails from scratch now takes 25 s instead of 99 s (reduced-scale decode plus two threads).
